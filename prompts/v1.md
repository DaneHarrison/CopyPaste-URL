# Website Capture and React/Tailwind Reconstruction

## Objective
Build a reproducible pipeline that ingests a public website starting from `START_URL`, captures its structure and assets, and recreates it as a React Router + Tailwind CSS project based on the template in `example/`. Produce a companion analysis of site weaknesses and document the output so another developer can extend or replatform it.

## Inputs
- `START_URL`: runtime-supplied, must be on the target domain.
- Baseline project in `example/` (React 19, React Router 7, Tailwind CSS v4, Vite 7, TypeScript 5.9).
- Working directories:
  - `output/` for the generated project.
  - `src/` for scraping utilities.

## Deliverables
- Reconstructed React project in `output/` mirroring the `example/` structure and using React Router for every unique page.
- `output/sitemap.md`: markdown sitemap for the discovered navigation hierarchy.
- `output/analysis.md`: recommendations covering UX, accessibility, SEO, performance, content, and technical stack observations.
- `output/README.md`: setup instructions, dependency list, generated file map, and summary of the new project structure.
- Stored assets (images, media, fonts) under `output/public/` with predictable per-page folders; font files de-duplicated under `output/public/fonts/`.
- Any additional supporting docs referenced above.

## Safety & Compliance
- Only crawl URLs on the same registrable domain as `START_URL`; skip subdomains unless explicitly linked and matching the same eTLD+1.
- Respect `robots.txt`, HTTP status codes, and rate limits; do not brute force or alter cookies.
- Immediately halt traversal on login walls, paywalls, or authenticated experiences; log the blocked URL in `output/sitemap.md`.
- Detect honeypots (hidden via CSS `display:none`, off-screen positioning, zero opacity, `aria-hidden`, or `tabindex=-1`) and exclude them from traversal.
- Run browser automations in headed mode with realistic viewport, user agent, scrolling, randomized delays, and limited parallelism to mimic human browsing.
- Do not submit forms, trigger purchases, or execute scripts that mutate remote state.

## Recommended Tooling
- Use Playwright or Puppeteer (JavaScript/TypeScript) or Playwright Python when needed; prefer the ecosystem that best integrates with existing repo tooling.
- Capture dependencies in `package.json` or `requirements.txt` and document commands to set up the scraper.
- Persist configuration in `src/` (e.g., `src/config.ts` or `.json`) to control crawl depth, request throttling, and ignored paths.

## Workflow
1. **Setup**
   - Initialize a fresh workspace under `output/` by copying the `example/` template.
   - Record environment prerequisites and install commands in `output/README.md`.
   - Configure linting/formatting to match the template (TypeScript strict, ESLint).

2. **Sitemap Discovery**
   - Load `START_URL` and collect internal links via navigation, header/footer menus, and contextual links.
   - Normalize URLs (strip query strings unless required, resolve relative paths) and deduplicate.
   - Limit traversal to a maximum crawl depth of 4 hops from `START_URL` and a maximum of 100 unique pages; expose overrides in configuration.
   - Persist traversal decisions (visited, skipped, blocked) and export to `output/sitemap.md` using nested bullet points to reflect hierarchy.

3. **Content Capture**
   - For each approved URL, save:
     - Page metadata (title, meta tags, canonical URL).
     - Extracted inline styles, linked CSS/JS references, and determine critical class usage.
     - Download referenced images, videos, and documents; preserve filenames, and organize under `output/public/assets/<route-slug>/`.
     - Fetch and deduplicate font files into `output/public/fonts/`.
   - Log any missing assets or blocked requests for manual follow-up.

4. **React Router Reconstruction**
   - Create route components under `output/src/routes/` mirroring each unique page; keep per-route components self-contained, no premature factorization.
   - Use Tailwind utility classes to match layout, typography, spacing, and colors. Translate repeated styles into Tailwind config extensions when helpful.
   - Honor global layout patterns in `output/src/App.tsx` and register routes via `output/src/main.tsx`.
   - Extract shared UI (navigation, footer, hero sections) into `output/src/components/` only when reused across multiple routes.
   - Replace inline scripts with idiomatic React patterns (hooks, event handlers) or document unsupported features.

5. **Styling & Assets**
   - Map CSS variables or custom styles to Tailwind tokens (`tailwind.config.ts`) as needed.
   - Embed downloaded fonts via `@font-face` declarations in `output/src/index.css` referencing the local files.
   - Replace direct asset URLs with imports from `output/public/` or `new URL` helpers consistent with Vite static handling.

6. **Quality Checks**
   - Ensure navigation works with React Router links and nested routes when appropriate.
   - Run `npm run lint` and `npm run build` to validate TypeScript and bundler integrity; capture results in `output/README.md`.
   - Verify the rebuilt site visually against references; note discrepancies in `output/analysis.md`.

7. **Site Understanding & Recommendations**
   - Summarize the site's purpose, target audience, and key offerings at the top of `output/analysis.md`.
   - Provide actionable recommendations across:
     - Accessibility (semantic structure, ARIA usage, contrast, keyboard flow).
     - SEO/content (metadata, heading hierarchy, load performance, structured data).
     - UX/design (information architecture, responsiveness, imagery).
     - Technical stack (hosting limitations, CMS/platform trade-offs, modernization opportunities).
     - Asset optimization (image formats, lazy loading, font subsets).
   - Highlight quick wins vs. longer-term improvements.

8. **Documentation**
   - Update `output/README.md` with:
     - Overview of the generated project.
     - Setup instructions (install, dev server, build, lint).
     - Route map referencing files (e.g., `src/routes/about.tsx`).
     - Asset organization schema and any manual follow-up notes.
     - Known gaps or assumptions (unsupported features, scripts skipped).
   - Include a changelog section summarizing automation steps and timestamps if feasible.

## Reporting & Logging
- Emit progress logs (console or file) for crawl status, errors, and decisions.
- Provide a final summary in the CLI/stdout that points to generated artifacts and highlights any blockers.

## Completion Criteria
- All deliverables exist in `output/` with consistent naming.
- React build succeeds without TypeScript or lint errors.
- `output/sitemap.md` includes every reachable page or documents exclusions.
- `output/analysis.md` offers at least 5 tailored recommendations with supporting rationale.
- README documentation enables a handoff to another developer without additional context.
